# ADR: Воспроизводимость и проверка учебных работ

**Title**: Выбор решаемой проблеммы и сервиса для его решения
**Decision**: Выбран сервис ClearML

## Background

В учебном процессе по направлению DS / ML студенты выполняют лабораторные работы, включающие:

- Исследовательский анализ данных 
- Обучение и сравнение нескольких моделей
- Подбор гиперпараметров
- Сохранение артефактов (модели, предобработка, отчеты)
- Подготовку финального проекта (демо, презентация)


В следствии чего, имеются следующие проблеммы:

1. Студент: 
    - Нет единого места для экспериментов
    - Сложно сравнивать запуски
    - Низкое качество работ
    - Фрустрация, потеря времени
2. Преподаватель: 
    - Ручная проверка 50+ ноутбуков
    - Невозможность воспроизвести результат
3. Методист: 
    - Нет возможности объективной оценки результатов разных студентов
4. Организация: 
    - Предоставление доступов
    - Дешевизна и простота содержания

## Considerations

Был произведён анализ альтернатив

| Критерий                    | ClearML                                                                 | MLflow                                                                 | Kubeflow                                      |
|-----------------------------|-------------------------------------------------------------------------|------------------------------------------------------------------------|-----------------------------------------------|
| Трекинг экспериментов       | Авто-лог через Task                                                     | log_param/log_metric; auto-logging для sklearn/PyTorch/XGBoost        | ML Metadata (K8s)                             |
| UI / Визуализация           | Готовый: сравнение + leaderboard                                        | Базовый: runs + метрики                                               | Сложный K8s Dashboard                          |
| Артефакты                   | Сложный K8s Dashboard                                                   | log_model + Registry                                                  | Artifact Store + MLMD                          |
| Оркестрация пайплайнов      | Artifact Store + MLMD                                                   | Внешние (Airflow, etc.)                                               | Native K8s (Argo/Tekton)                       |
| Автоматический захват контекста | Код + Docker + окружение                                             | Частичный: авто-лог метрик, но окружение (conda/docker) требует ручной настройки | Явные Docker-образы                            |
| Порог входа для студента    | Низкий (2 строки кода)                                                  | Низкий (2 строки кода)                                                | Высокий (K8s экспертиза)                       |
| Self-hosted сложность       | Низкая (Docker Compose)                                                 | Низкая (сервер + БД)                                                  | Высокая (полный K8s)                           |


## Decision Outcome

В результате проведённого анализа был выбран *ClearML* последующим критериям:

| Критерий                         | Почему ClearML                                                                                                                              |
|----------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------|
| Баланс простоты и функциональности | Одна строка `Task.init()` дает автоматический захват кода, окружения, метрик и артефактов — идеально для студентов.                        |
| UI/UX для проверки               | Интуитивный дашборд с сравнением экспериментов, графиками, артефактами и комментариями — экономит время преподавателя.                     |
| Воспроизводимость                | Автоматический snapshot кода (git), окружения (conda/pip) и данных — гарантия, что работа запустится у преподавателя.                      |
| Масштабируемость                 | ClearML Agent позволяет студенту отлаживать код локально, а запускать обучение на GPU-сервере вуза без изменений в коде.                   |
| Гибкость интеграции              | Поддерживает любые фреймворки (sklearn, PyTorch, TF), хранилища (S3/MinIO), и может работать в гибридном режиме (онлайн/офлайн).           |
| Путь развития                    | По мере роста курса можно добавить оркестрацию, мониторинг моделей, автоматизацию — без смены инструмента.                                 |

## Consequences
1. Для студентов
    - Меньше времени на настройку окружения, больше на ML
    - Прозрачное сравнение своих экспериментов
    - Профессиональный инструмент в портфолио
2. Для преподавателей
    - Сокращение времени проверки на 30-50%
    - Объективная оценка на основе метрик и артефактов
    - Возможность давать персонализированный фидбек в UI
3. Для учебного процесса
    - Воспроизводимость работ повышает академическую честность
    - Данные об экспериментах группы помогают улучшать курс
